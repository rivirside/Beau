# Philosophy

Four commitments. Every screen should be explicable by one of them, and anything
that is not should be cut.

## 1. Beau proposes; you decide

A session is a proposal, never an order. Every exercise can be swapped or
rejected, and every rejection carries a reason that teaches the app — no such
equipment, not today, never again. The engine is an assistant with a very good
memory, not a coach with authority.

## 2. Everything stays on this device

No account, no server, no telemetry. Your training log is yours in the plainest
sense: it exists in one place, and Export is the only way it leaves. This is a
constraint the design accepts gladly, because it forces the intelligence to be
explicable and local rather than a model somewhere else.

## 3. Every number explains itself

A prescribed weight says why it is that weight. A recovery percentage says which
sets caused it and when. A pick says which muscle it is for. If the app cannot
say why, it should not say it.

## 4. Train the body you can understand

The same anatomy that decides what you are owed is the anatomy you can study.
The rest timer quizzes you on the muscle you just felt working. Understanding
what you train is not a separate product; it is the point.

## What that means for structure

Four places, each with one job:

| Tab | Job | Question it answers |
| --- | --- | --- |
| **Today** | The daily loop: review the proposal, train, finish. | *What am I doing now?* |
| **Progress** | The state of your body and your lifts: recovery, weekly volume, exercise trends, session history. | *How am I doing?* |
| **Learn** | The anatomy library and the study deck. | *What is this muscle?* |
| **Settings** | Everything you configure and forget: profile, plan, gym, preferences, data, updates. | *How is Beau set up?* |

Recovery lives under **Progress**, not Today. It describes your body's state,
which is an input to the proposal, not part of it. Today shows only the
proposal.

The plan (which days, which focus, how long) is configuration. It lives under
Settings with a shortcut from Today's header, the way iOS puts a thing where you
set it and lets you reach it from where you feel its effect.

## Setup

Setup is a real phase, not a form. It walks the four things the engine needs to
propose well on day one, in the order they matter:

1. **You** — units, bodyweight, experience. Experience sets default volume.
2. **Your week** — a split and a schedule. Nothing can be proposed without one.
3. **Your gym** — what can be prescribed, and how weights round.
4. **Your lifts** — working weights for four anchor movements, optional. Each one
   seeds a progression state, so the first session is not a cold start on the
   lifts that matter most. Skippable; Beau asks again in-session for anything
   it does not know.

## Visual language

iOS system conventions, deliberately: inset grouped lists, disclosure rows that
push a page, a large title that collapses, a segmented control for a small
choice, a switch for a boolean, a footer sentence under a group that says what
it does. Not because it is fashionable, but because the target is a native iOS
app and a user should not have to learn two interfaces for one product.
